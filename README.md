Инженерный учебный проект по разработке воспроизводимого программного комплекса аналитики продаж: переиспользуемая доменная библиотека, исполняемое CLI-приложение, автоматизированное тестирование с измерением покрытия, сборка документации и контейнеризация.

---

## 📌 О проекте и решаемая задача

Проект предназначен для автоматизации первичной обработки и агрегации логов продаж. Система решает следующие задачи:
1. **Надежное чтение и валидация:** построчный разбор UTF-8 CSV-логов с устойчивостью к битым строкам (пропуск некорректных записей без падения приложения).
2. **Бизнес-расчеты:** вычисление стоимости каждой позиции, суммирование по категориям товаров, поддержка накопительных или акционных скидок, фильтрация позиций по порогу суммы.
3. **Формирование отчетов:** генерация унифицированного текстового отчета согласно утвержденной спецификации.
4. **Архитектурная независимость:** доменные правила вынесены в отдельный переиспользуемый пакет `sales`, а доставка логики пользователю реализована через консольное приложение `app.main` (CLI).

## 🚀 Быстрый старт

### Предварительные требования
* Python 3.10, 3.11 или 3.12;
* Утилита `make` (GNU Make);
* Опционально: `docker` и `docker compose`.

### 1. Подготовка окружения и установка
Все стандартные действия автоматизированы через корневой `Makefile`.

```bash
# Создание виртуального окружения и установка в режиме разработки
make install
```

Эта команда автоматически создаст `.venv`, установит зависимости из `requirements-dev.txt` и зарегистрирует пакет `sales` в режиме редактирования (`pip install -e .`).

## 💻 Использование приложения

### Запуск через консольную команду `sales`
После установки пакета в окружение доступна консольная утилита:

```bash
# Активация окружения (если не активировано)
source .venv/bin/activate

# Базовый запуск с выводом отчета в stdout:
sales -i data/sample_sales.csv

# Запуск с применением скидки 10% и сохранением отчета в файл:
sales -i data/sample_sales.csv -d 10.0 -o report.txt

# Фильтрация позиций с суммой не менее 30.0:
sales -i data/sample_sales.csv -t 30.0
```

### Запуск напрямую через Python
Запускаемая часть приложения доступна через модуль `app.main`:

```bash
python3 -m app.main -i data/sample_sales.csv
```

### Пример входных данных (`data/sample_sales.csv`):
```text
tea,drinks,7.0,5
coffee,drinks,12.5,3
croissant,bakery,15.2,2
baguette,bakery,25.2,1
apple,fruit,4.0,6
```

### Ожидаемый результат:
```text
Report
------
drinks: 72.5
bakery: 55.6
fruit: 24.0
------
Total: 152.1
```

## 🧪 Тестирование и отчет о покрытии

Тестовый набор покрывает как позитивные, так и граничные/негативные сценарии (деление на ноль, дробные количества, нечисловые цены, пустые файлы, отсутствующие поля):

```bash
# Запуск тестов:
make test

# Запуск тестов с подробным отчетом о покрытии кода (coverage):
make coverage
```

Текущее покрытие кода тестами составляет **99%**. HTML-отчет о покрытии сохраняется в директорию `htmlcov/index.html`.

## 📚 Сборка проектной документации

Документация собирается автоматически через **Sphinx** с поддержкой **MyST-Parser** (Markdown):

```bash
make docs
```

Сгенерированные HTML-страницы сохраняются в `docs/build/html/index.html`. Документация включает руководство пользователя, спецификацию, архитектуру и автоматически сгенерированный API-справочник модулей.

## 🛠 Сводка команд автоматизации (`Makefile`)

| Команда | Описание |
| :--- | :--- |
| `make help` | Вывести интерактивную справку по всем доступным командам |
| `make install` | Создать `.venv` и установить зависимости и пакет в editable-режиме |
| `make test` | Запустить модульные и интеграционные тесты (`pytest`) |
| `make coverage` | Сгенерировать терминальный и HTML-отчет о покрытии тестами |
| `make run` | Запустить CLI-приложение с демонстрационным файлом продаж |
| `make build` | Собрать пакеты wheel и sdist в директорию `dist/` |
| `make docs` | Собрать HTML-документацию проекта через Sphinx |
| `make docker-build` | Собрать Docker-образ приложения (`sales:0.1.0`) |
| `make docker-run` | Выполнить расчет внутри изолированного Docker-контейнера |
| `make compose-up` | Запустить локальное Compose-окружение |
| `make compose-down` | Остановить Compose-контейнеры |
| `make clean` | Удалить кэши (`__pycache__`, `.pytest_cache`), отчеты и артефакты сборки |
